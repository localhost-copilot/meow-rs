# OpenClash 内存优化与性能验证

本轮基线为 `c36e3ad`，候选代码为 `ff164d4`，均位于
`perf/openconnect-four-flow`。同时在 ARM64 OpenClash 上将现有的
GeoSite 加载模式从 `standard` 调整为 `memconservative`。
以下路由器内存差值包含代码优化和配置调整两部分。

## 改动

- `d1d4713`：启动时只解析一份规则集，DNS、控制器和路由规则引用相同的
  不可变匹配器，去掉一次被丢弃的完整解析和一份长期保留的重复匹配器。
- `ff164d4`：一次配置加载中，行为、格式和内容字节完全相同的文件或 HTTP
  规则集共享匹配器。提供者名称、更新时间和刷新替换槽保持独立；去重表及
  内容键在加载结束后释放。匹配路径没有新增哈希查询或锁。
- 使用现有的 `memconservative` 加载器：按配置引用加载 GeoSite 分类。
  未改变 `standard` 的语义，也未缩减协议缓冲区、连接队列或并发上限。

这份配置中，GeoSite 由 DNS `nameserver-policy` 引用；完整数据库包含
1,892 个分类，实际只需 1 个。两个最大的域名 MRS 规则集内容也完全相同。

OpenClash 的持久设置方式如下；其配置生成脚本会将此值写入运行时 YAML：

```sh
uci set openclash.config.geodata_loader=memconservative
uci commit openclash
/etc/init.d/openclash restart
```

直接运行内核时，对应 YAML 字段为 `geodata-loader: memconservative`。

## ARM64 实机内存

使用同一台 ARM64 ImmortalWrt 路由器、同一份 OpenClash 配置及规则缓存。
测量 `/proc/<pid>/status`，1 MiB = 1,024 KiB；RSS 为进程驻留内存，
不是虚拟地址空间，也不是整台路由器的内存使用量。

| 指标 | 基线 | 候选版，连接预热后 |
| --- | ---: | ---: |
| RSS | 109,096 KiB / 106.54 MiB | 38,020 KiB / 37.13 MiB |
| RSS 历史峰值 | 131,824 KiB / 128.73 MiB | 48,812 KiB / 47.67 MiB |
| 匿名驻留内存 | 98,688 KiB | 27,680 KiB |
| 文件驻留内存 | 10,408 KiB | 10,340 KiB |

此样本的 RSS 减少约 **65.1%**，约 **69.4 MiB**。基线是已运行服务的空闲
采样；候选版在启动、仪表盘访问、两条 OpenConnect HTTPS 健康检查和 UDP
探测后采样。候选版三个先后采集的 RSS 样本为 37,592、37,844、38,020 KiB，
核心 PID 未改变，持续运行期间未重启以降低内存读数。
两个进程运行时长不同，因此历史峰值不代表相同持续时间的负载峰值。

## GeoSite 行为与查找耗时

使用路由器同一份 GeoSite 文件，将全部分类中的域名值、`www.` 前缀和
`.invalid` 后缀变体去重，加入空字符串和额外的未匹配域名，共 931,129 个查询。
对配置引用的分类逐个比较 `standard` 和 `memconservative`：分类条目数相同，
所有查询结果一致，其中 233,053 个匹配。

在 Apple M4 上以 release 模式交错执行五轮，931,129 次查询的耗时中位数为
212.271 ms 和 212.521 ms，相差约 +0.12%。这是同一查询实现加载不同大小
数据库后的局部测量；不等同于完整 DNS 请求延迟。

## 四流吞吐

使用两个 release 二进制，分别从 `c36e3ad` 和 `ff164d4` 构建，均为默认完整
功能。Apple M4，Rust 1.98.0；本地 Docker ocserv 测试夹具和合成凭据。
构建、完整测试和 GeoSite 计时在 iperf 测量前完成。

匿名 A/B 配置沿用[前一轮报告](openconnect-four-flow-2026-09-10.md)中的客户端
选项和 DTLS MTU，使用实际连接所协商的 AES-256-GCM。每次在 ocserv 确认
DTLS 会话建立后计时。没有额外注入 RTT；不使用私有节点做吞吐压测。

每个二进制、每个配置各启动三次，轮换先后顺序。以下为 iperf3 接收端吞吐的
三次中位数，单位 Mbit/s；同时收发为每方向四流，总计八条数据连接。

| 配置 | 负载 | 基线 | 候选版 | 变化 |
| --- | --- | ---: | ---: | ---: |
| A | 四流上传 | 667.342 | 673.154 | +0.87% |
| A | 四流下载 | 772.455 | 773.730 | +0.17% |
| A | 同时收发：上传 | 76.741 | 83.542 | +8.86% |
| A | 同时收发：下载 | 667.305 | 691.267 | +3.59% |
| B | 四流上传 | 711.617 | 709.560 | -0.29% |
| B | 四流下载 | 821.197 | 815.645 | -0.68% |
| B | 同时收发：上传 | 83.492 | 78.835 | -5.58% |
| B | 同时收发：下载 | 733.495 | 738.353 | +0.66% |

所有 [48 个测量值](openclash-memory-2026-09-10.samples.json)均保留，没有剔除
低吞吐样本。B 配置同时收发上传的差异触发了单独的交错复测。

### B 配置同时收发复测

保持两个二进制及全部连接参数不变，额外各启动三次，仅测试同时收发，
交错顺序为基线/候选、候选/基线、基线/候选。该批次没有之前单向负载的
预热过程，因此单独呈现，不与第一批混合计算中位数。

| 方向 | 基线 | 候选版 | 变化 |
| --- | ---: | ---: | ---: |
| 上传 | 82.092 | 84.403 | +2.82% |
| 下载 | 726.284 | 749.873 | +3.25% |

[12 个复测值](openclash-memory-2026-09-10.bidir-followup.json)均保留。
三对上传结果的候选版均高于对应基线，未复现第一批中位数的下降。
综合两批结果，未发现稳定的吞吐回退；第一批的负向结果和测试波动仍须保留，
不能用补测中的提升保证所有场景都更快。

## 验证与构建

- 默认 CI 单元及集成测试清单：2,182 项通过，0 失败，4 项原有忽略项。
- 全工作区 `cargo clippy --locked --all-targets -- -D warnings`、格式和差异检查通过。
- 新增回归覆盖：DNS/路由共享规则匹配器，以及内容相同的两个提供者独立刷新。
- 路由器运行时 YAML 配置校验通过。替换后仍有 98 个规则提供者、553,129 条
  提供者内容、134 条路由规则和 55 个代理注册项，与替换前一致。
- OpenClash 启动完成，持久配置和运行时 YAML 均为 `memconservative`。
- Zashboard HTML 及 10 个资源、Metacubexd HTML 及 6 个资源返回 200；
  控制器带令牌返回 200，未认证返回 401。
- 透明代理 HTTPS 返回 204；两条 OpenConnect HTTPS 健康检查通过，并捕获到
  两个连接双向收发的 DTLS 1.2 application data。
- fake-IP STUN 通过 UDP TPROXY 7895 成功，控制器记录上传 20 字节、下载 32
  字节；没有生成内核自管的 `inet meow_tproxy` 表。

ARM64 构建使用 Rust 1.91.1、Zig 0.13.0：

```sh
cargo zigbuild --release --locked --target aarch64-unknown-linux-musl -p meow-app
```

输出为已剥离的静态 ELF，没有 INTERP 段或 NEEDED 共享库。二进制 SHA-256：

```text
f4133e25f1dee77a6f040438109ae109448ff3b597dd9d8b104df248eddeeaba
```

本轮未修改 OpenConnect 传输实现，也未重测 mihomo；前一轮报告中的同时收发
性能差距仍然适用。有限的本机吞吐样本和短时路由器验证不能覆盖所有 WAN
延迟、抖动、丢包或长时间运行场景。仓库中的报告只保留匿名配置与汇总结果，
不包含私有 YAML、节点、地址、凭据或抓包。
